# Domain docs

The frontend, backend, and scenarios share one domain context. Read the [glossary](../../CONTEXT.md) before changing domain behavior or terminology. Use its terms in issues, proposals, hypotheses, and tests.

## Feature notes

- [Practice](../features/practice.md) covers scenario data, session and API behavior, outcomes, scoring, and replay.
- [Voice calls](../features/voice-calls.md) covers microphone input, reply retry, boss interruptions and silence, the transcript, and playback.
- [Providers](../features/providers.md) covers local and mock dialogue, OpenRouter, and generated Thai audio.

Read the matching notes before editing a feature. Update the affected notes when a change alters the behavior they describe. Read relevant ADRs in `docs/adr/` when present. If a proposal conflicts with an existing ADR, name it and explain why the decision may need to be revisited.
