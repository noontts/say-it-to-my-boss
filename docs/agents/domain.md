# Domain docs

This repository has a single domain context. The frontend, backend, and scenarios share the root `CONTEXT.md` glossary and architecture decision records in `docs/adr/`.

Before exploring a task, read `CONTEXT.md` and any ADRs relevant to the area if those files exist. Continue if they are absent. The domain-modeling skill adds glossary entries and ADRs as terms and decisions are settled.

Use glossary terms in issue titles, proposals, hypotheses, and test names. When a proposal conflicts with an existing ADR, name the ADR and explain why the decision may need to be revisited.
